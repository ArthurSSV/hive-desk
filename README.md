# Матрёшка — Челлендж

Отчётность группы по проп-челленджу FundedHive (cTrader): кабинет трейдера и панель админа со светофором тильта.

## Как устроено

| Часть | Где работает | Что делает |
|---|---|---|
| Сайт (Next.js) | Vercel | Регистрация и вход, кабинет трейдера, панель админа, подключение cTrader и MetaMask |
| База и авторизация | Supabase | Профили, счета, сделки, дневная статистика, дневник, правила. Доступ по ролям (RLS) |
| Синхронизация | GitHub Actions, каждые 15 минут | Забирает сделки из cTrader Open API, считает дневную статистику, статус фазы и флаги, шлёт Telegram-алерты |

Трейдер регистрируется по ссылке `/register`, входит через cTrader ID (доступ только на чтение) и выбирает счёт челленджа. После этого он автоматически появляется в панели админа.

## Запуск — по шагам

### 1. Supabase
1. Создайте проект на supabase.com (регион Frankfurt).
2. SQL Editor → вставьте содержимое `supabase/schema.sql` → Run.
3. Назначьте себя админом (до регистрации на сайте):
   ```sql
   insert into public.admin_emails (email) values ('ваш@email.com');
   ```
   Если уже зарегистрировались: `update public.profiles set role = 'admin' where email = 'ваш@email.com';`
4. Authentication → URL Configuration: **Site URL** = адрес сайта на Vercel, в **Redirect URLs** добавьте `https://<ваш-сайт>/auth/callback`.
5. Project Settings → API: скопируйте `URL`, `anon` и `service_role` ключи.

### 2. cTrader Open API
1. openapi.ctrader.com → ваше приложение → статус должен быть **Active**.
2. Добавьте Redirect URI: `https://<ваш-сайт>/api/ctrader/callback`.
3. Скопируйте Client ID и Client Secret.

### 3. Vercel
1. New Project → импортируйте этот репозиторий.
2. Environment Variables — все переменные из `.env.example`.
3. Deploy. После деплоя проверьте, что `NEXT_PUBLIC_APP_URL` совпадает с реальным адресом.

### 4. GitHub Actions (синхронизация)
Репозиторий → Settings → Secrets and variables → Actions → добавьте секреты:
`NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `CTRADER_CLIENT_ID`, `CTRADER_CLIENT_SECRET`, и при желании `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ETHERSCAN_API_KEY`, `FUNDEDHIVE_ADDRESSES`.
Первый запуск вручную: Actions → Sync cTrader → Run workflow.

### 5. Telegram (необязательно)
1. @BotFather → `/newbot` → токен в `TELEGRAM_BOT_TOKEN`.
2. Напишите боту любое сообщение, откройте `https://api.telegram.org/bot<токен>/getUpdates` и возьмите `chat.id` → `TELEGRAM_CHAT_ID`.

### 6. Проверка
1. Зарегистрируйтесь своим email — откроется панель админа.
2. С другого email зарегистрируйте тестового трейдера → «Войти через cTrader ID» → выберите счёт, этап и начальный баланс.
3. В панели админа появится трейдер; через «Синхронизировать сейчас» в его карточке подтянутся сделки.

## Локальная разработка
```bash
cp .env.example .env.local   # заполнить
npm install
npm run dev                  # сайт на localhost:3000
npm run sync                 # разовая синхронизация
npm test                     # проверки движка метрик
```

## Что важно знать
- **Дневная просадка считается по закрытым сделкам.** Плавающий P&L открытых позиций в версии 0.1 не учитывается, поэтому внутри дня реальная просадка может быть больше. Следующий шаг — добавить подписку на цены и расчёт эквити.
- **Начальный баланс** лучше указать вручную (размер счёта). Если оставить пустым, он восстанавливается по текущему балансу и истории сделок.
- **Каждая фаза — отдельный счёт cTrader.** После прохождения фазы трейдер подключает новый счёт и выбирает этап «Фаза 2» или «Funded».
- **Лоты** пересчитываются как для FX (1 лот = 100 000 единиц); для металлов и индексов значение условное, но для флага «рост лота» важна только динамика.
- Пороги и цели меняются в разделе «Правила» без правки кода.
